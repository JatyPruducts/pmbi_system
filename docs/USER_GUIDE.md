# PMBI — пользовательская документация

Документ описывает, что находится (и должно находиться) на страницах веб-приложения PMBI.

## Роли и доступ

- `ADMIN` — полный доступ ко всем страницам.
- `HR` — главная, HR, сотрудники, конструктор.
- `TEAMLEAD` — главная, команда, сотрудники, конструктор.
- `EMPLOYEE` — главная, ЛК, конструктор.

Если роли недостаточно, переход перенаправляется на главную.

## Страница `Вход` (`/login`)

- Поля: `Email`, `Пароль`.
- Кнопка: `Войти`.
- Назначение: получить JWT, сохранить сессию и перейти на главную.
- Для демо доступны тестовые учётные записи (после seed).

## Страница `Главная` (`/`)

Центральный информационный дашборд.

Содержит:

- **Сводные KPI-карточки**
  - количество сотрудников;
  - количество подразделений;
  - количество открытых алертов;
  - средний уровень стресса (burnout).
- **Графики**
  - `Стресс по подразделениям` (bar/heat-style агрегат);
  - `Результативность / Счастье` (scatter: Likert vs KPI);
  - `Компетенции: идеал vs текущий` (radar).
- **Блок последних алертов**
  - список последних предупреждений/критических событий с severity.

Назначение главной: дать быстрый управленческий срез состояния компании сразу после входа.

## Страница `HR` (`/hr`)

Дашборд HR-аналитики:

- кнопка пересчёта аномалий (`Пересчитать алерты`);
- график стресса по подразделениям;
- сравнение компетенций (идеал/текущий профиль);
- scatter продуктивности и «счастья».

Важно: данные для HR анонимизируются (без показа сырых индивидуальных ответов).

## Страница `Команда` (`/lead`)

Кабинет руководителя команды:

- scatter-график команды (`результативность / счастье`);
- radar-профиль компетенций команды/сотрудника в зоне ответственности.

Назначение: оценка продуктивности через психологический климат команды.

## Страница `ЛК` (`/me`)

Личный кабинет сотрудника:

- персональные рекомендации по soft-skills;
- radar-профиль `Цель vs Вы`.

Назначение: самооценка и персональные рекомендации по развитию.

## Страница `Сотрудники` (`/employees`)

Табличный просмотр сотрудников для ведущих ролей:

- доступ: `ADMIN`, `HR`, `TEAMLEAD`;
- колонки: `external_id`, `user_id`, подразделение, позиция, менеджер;
- кнопка `Обновить` для перечитывания данных.

Особенности доступа:

- `ADMIN` и `HR` видят полный список;
- `TEAMLEAD` видит только свою команду и себя (ограничение на backend).

## Страница `Конструктор` (`/builder`)

Инструмент визуальной сборки BI-запросов и сохранения конфигурации:

- выбор исходной таблицы (`employees`, `metric_values`, `kpi_types`, `org_units`, `positions`) и вход в рабочую область;
- верхняя панель операций: `JOIN`, `SELECT`, `GROUP BY`, `FILTER`, `ORDER BY`, `LIMIT`;
- функции агрегации в `SELECT`: `COUNT`, `SUM`, `AVG`, `MIN`, `MAX`;
- центральная область: таблица результата (как вывод SQL-запроса);
- правая панель: история операций, SQL и кнопка сохранения;
- автоматический предпросмотр после каждого добавления/изменения операции.

Назначение: собрать аналитический запрос без ручного SQL и быстро проверить результат перед публикацией на дашборд.

## Верхнее меню

- `Главная` — всегда после авторизации.
- `HR` — для `HR`, `ADMIN`.
- `Команда` — для `TEAMLEAD`, `ADMIN`.
- `Сотрудники` — для `HR`, `TEAMLEAD`, `ADMIN`.
- `ЛК` — для `EMPLOYEE`, `ADMIN`.
- `Конструктор` — для всех авторизованных ролей.
- `Выход` — очистка токена и переход на `/login`.
